## 3. P1 · 错误态补漏（0.5 天）

已有 11 个错误码映射，但 PLAN §8 承诺过的三件事**根本没实现**：

### 1.1 人机验证 / 验证码检测 ⚠️ 最高价值
- **现状**：0 检测。`deepseek-window.cjs:12` 只有一句注释提到「验证码必须本人处理」，没有任何代码。PLAN §8 明确写过「检测到验证码就亮黄灯并弹『点我去验证』」——**这是欠账**。
- **做法**：`page-scripts.cjs` 加 `detectChallenge()`，探针查 `iframe[src*="captcha"]`、`[class*="turnstile"]`、`[class*="hcaptcha"]`、页面文本含「人机验证 / 请完成验证」。
- **链路**：命中 → `engine.status` 返回 `{status:"warn", code:"captcha"}` → 面板状态灯变黄 + 底栏出按钮「点我去验证」→ 点一下 `openDeepSeekWindow({visible:true})`。
- **改文件**：`engine/page-scripts.cjs`、`engine/web-page.cjs`、`ui/panel.js`、`main/index.cjs`

### 1.2 断网 / 网络错误专属文案
- **现状**：`did-fail-load` 只 `console.error`，用户看到的是一句笼统的「打不开 DeepSeek 网页」。
- **做法**：按 Chromium 错误码映射：`-106` → 「网络已断开，检查连接后点重试」；`-105` → 「DNS 解析失败」；`-118` → 「连接超时」；`-102` → 「连接被拒绝（可能被墙/防火墙拦）」。
- **改文件**：`main/deepseek-window.cjs`、`ui/panel.js`

### 1.3 登录态过期主动提示
- 已有 8s 轮询 `pushEngineStatus`，但 `signedIn:false` 时面板没有显眼提示。
- **做法**：面板顶部加一条细提示条「DeepSeek 登录已过期 · 点这里重新登录」，可关闭。

**P1 验收**：拔网线翻译 → 5s 内出「网络已断开…」；手动退出登录 → 30s 内出黄灯 + 提示条；用 dev flag 伪造验证码节点 → 出黄灯 + 「点我去验证」。
**这一步做完，M5 那句正式的验收标准（拔网线/未登录/超长都有可读提示，不崩）就算达标了。**

## 5. P5 · 深浅色 —— ❌ 已取消（用户决定，不改动）

**决定**：保持现有 9 套手动配色预设的模式，不做「跟随系统」自动切换。

- **理由**：现有预设里已经有 6 套亮色（纸白/米黄/柠檬/薄荷/天空/樱粉），手动选已经覆盖了亮色需求；再加「跟随系统」只会跟预设按钮的选中态打架，多一个复杂度换不来实际收益。
- **后果**：`tokens.css` 里那个空的 `prefers-color-scheme: light` 媒体查询**保留原样**，注释改成「按设计不做跟随系统，靠预设切换」。不做任何代码改动。
- **连带影响**：`ball.css` 那 4 处硬编码 `rgba(255,255,255,…)` / `rgba(0,0,0,…)` 也**不动**——因为预设是靠 JS 覆盖 CSS 变量实现的，亮色预设下这 4 处如果真的有视觉问题，属于现存 bug，另开任务处理，不混进 M5。

## 8. P2 · 流式输出（1 天，默认关；⚠️ 待你决定做不做）

### 8.0 「流式」到底是干嘛的 —— 先讲清楚

现在这个球的翻译体验是这样的：

```
你点翻译 → 面板空白，什么都看不到 → 后台偷偷轮询 DeepSeek 页面
         → 等到译文整段生成完、且连续 2.4 秒不再变化
         → 才"啪"一下把整段译文甩到面板上
```

**问题**：DeepSeek 生成一段 300 字的译文要 5~10 秒。这 5~10 秒里面板一直是空的，你不知道它是在干活、还是卡死了。所以你以前才会遇到「翻译卡住不动」那种怀疑。

**流式**就是把这段时间利用起来：译文字一出来一个字就往面板上推，效果跟人打字一样：

```
你点翻译 → 0.8s 后屏幕上开始咕嘟咕嘟冒字："人工智能正在深刻地改变……"
         → 你一眼就知道它在干活，心里有底
         → 就算中途想取消，看到前两句也够判断了
```

**这不是新功能，是把等待过程可视化**。三个实际收益：

| 收益 | 说明 |
|---|---|
| 不用干等 | 首字 0.8s 就能看到，不用盯着空面板猜 |
| 早发现翻错 | 译文跑偏时，前两句就能看出来，按 Esc 直接停，不用等全文 |
| 心里有底 | 长文本 10 秒的等待，从「怀疑卡死」变成「看着它干活」 |

**代价 / 风险（必须让你知道）**：
- 它改的是全项目最敏感的一段代码（`waitForReply` 轮询）。PLAN §16「翻译卡住」和 §17「多翻几次不出来」两次事故，根都在这条链路上。
- 所以计划里把它**默认关**，你在设置里手动开。开了不满意，关掉就退回现在的行为，零风险。

**一句话总结**：流式 = 让译文边生成边显示，治的是「等待时以为卡死」这个体验问题。不是必须做，但做了体验提升最直观。

### 8.1 实施方案

- **现状**：`waitForReply` 轮询页面文本，`stable >= STABLE_POLLS` 才返回整段，中间从不外传。
- **做法**：轮询里每次 `last` 变化 → 通过 `onDelta(chunk)` 上推；`index.cjs` 用 `webContents.send("translate:delta")` 发给面板；面板增量渲染。
- **四条硬约束（写死，不许违反）**：
  1. **完成判据不许改**：仍然只认「文本连续 N 次不变」。§17 那个 bug 就是因为信了 `generating === false` 这个恒假的信号，**绝不能再引入任何"加速完成"信号**。
  2. **限流截断要照旧报错**：流式下若回复异常短，仍要走 §17 的「像被限流截断了」提示，不能因为"已经显示了半句"就当成功。
  3. **面板不闪**：`out` 元素重写用 `requestAnimationFrame` 合并，且锁住滚动位置。
  4. **Esc 可中断**：已吐出的部分保留，末尾标「已取消 · 点重试」，不整块清空。
- **开关**：`store.cjs` 加 `streaming: false`（默认关），设置里可开。
- **改文件**：`engine/web-page.cjs`、`main/index.cjs`、`preload/panel.cjs`、`ui/panel.js`
